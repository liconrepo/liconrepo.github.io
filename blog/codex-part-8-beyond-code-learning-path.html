The series so far has been about Codex as a coding agent. But the same ChatGPT account also opens doors that are not about code: a mode called ChatGPT Work for finished documents and research, an always-on helper called a dot, image generation, web search and a site builder. Many people who start with Codex are not writing software at all. This final part does two jobs. First, it maps what surrounds Codex and what the docs say about how mature each piece is. Second, it gives you a learning path: a first-week plan, practice exercises, the official resources, and a one-page quicksheet of the whole series.

Part 8 in 60 seconds
  • In the ChatGPT desktop app you choose between Chat (questions), ChatGPT Work (delegate a task and get a reviewable result) and Codex (developer tools and technical detail). They share usage limits.
  • You do not need to be a programmer. The docs give example Work prompts for a presentation, a comparison spreadsheet and a weekly update.
  • Dots, Sites and some other features are rolling out gradually or are in beta. The docs define five maturity labels, and you should read them before relying on a feature.
  • A week of short daily steps is enough to build a solid foundation. The plan below links every day to a part of this series.
  • OpenAI publishes use cases, videos, a free AI Foundations course, and programs for students and open-source maintainers. This series is a snapshot from October 2026, so trust the official docs when something differs.

1. Codex and the products around it

Back in Part 1 I described Codex as OpenAI's coding agent: it reads your project, edits files and runs commands, and it lives in the ChatGPT desktop app, a terminal (the CLI), an editor extension, the cloud and on mobile. The official docs now describe all of this as one family. The glossary even defines ChatGPT desktop app as the app that holds ChatGPT and Codex together, including Chat and Work, projects, file previews, scheduled tasks and developer tools.

In the desktop app you pick how you want to work. The “Use ChatGPT” page puts it in a three-row table:

Two more ideas sit next to these. A dot is an always-on agent that keeps track of an ongoing responsibility between conversations. Sites lets you build, host and share a website by describing it. Both are explained in section 2.

2. What each piece does, and what is stable

These products change faster than the developer tools, so I will describe each in a few plain sentences and point to the official page. The first table is a map. The second one is about trust: how much the docs promise.

PieceWhat the docs say it isHow it relates to Codex
ChatGPT WorkA way to delegate real work. It can plan a task, gather context, use tools and carry it to a result you review, such as a brief, deck, analysis, recurring update or file. See Get started with ChatGPT Work.The docs say that if you used Codex for non-coding work you can stay in Codex or use Work, which gives the same core capabilities with an experience designed for everyday work.
ProjectsA place to keep related chats, files, instructions and sources together. See Projects and chats.The Codex CLI treats the directory where you start it as the project. Durable guidance belongs in AGENTS.md (Part 2).
PluginsBundles of reusable workflows that can include skills and MCP servers, usable in Chat, Work and Codex. See Plugins.Same idea as Part 6. In the CLI, /plugins opens the plugin browser. The docs say the IDE extension does not support plugins.
Image generationCreate and edit images, such as UI assets, banners and illustrations. See Image generation.In Codex, describe the image or include $imagegen in the prompt. Attach a reference image with -i or --image. The docs say built-in generation uses gpt-image-2 and counts toward your general Codex limits.
Web searchA first-party search tool. The docs say to treat all web results as untrusted input. See Web search.In the CLI, local chats use cached search by default. Pass --search for live results, or set web_search in config.toml to disabled, cached, indexed or live.
SitesBuild, host and share a website, web app or game by describing it in ChatGPT or Codex. See Sites.You can start from either product. The docs list unsupported uses, so read that section before you plan a real project.
DotsAn always-on agent with its own cloud computer and browser that follows through between conversations. See Meet dots.A dot can start Work or Codex tasks, and continue existing local Codex tasks on a connected computer. Those tasks count toward the usual limits.

Analogy. Think of an office. Chat is a colleague you ask a quick question at their desk. Work is a colleague you hand a brief to and review the result later. Codex is the engineer who works inside your code. A dot is more like an assistant who owns an ongoing responsibility and reports back when you need to decide something.

How much can you rely on each feature?

The docs have a Feature Maturity page. It says some ChatGPT and Codex features ship behind a maturity label so you can see how reliable they are and what support to expect. Here are its five labels, in my words:

LabelMeaningOfficial guidance
Under developmentNot ready for use.Don't use.
ExperimentalUnstable. OpenAI may remove or change it.Use at your own risk.
BetaReady for broad testing, but some aspects may change.OK for most evaluation and pilots; expect small changes.
StableFully supported and documented; behaviour stays consistent.Safe for production use; removals go through deprecation.
DeprecatedStill available but no longer recommended.Avoid new use and plan to migrate.

Here is what I found labelled in the pages I read, as of 18 October 2026. Labels move, so run the command shown or open the page to check.

FeatureWhat the docs say
Hooks, goals, subagent collaboration (multi_agent), Fast mode, apps, shell toolsListed as Stable in the common feature-flag table in Config basics.
Memories (memories)Listed as Experimental and off by default in the same table.
RulesThe Rules page says rules are experimental and may change.
Legacy web search flagsListed as Deprecated. Prefer the top-level web_search setting.
SitesThe pricing FAQ says Sites is included with eligible plans during public beta.
GitLab merge request reviews, Composer Predictions, device code sign-inDescribed as beta on their pages.
Dots“Rolling out gradually” to eligible accounts. The docs list plan and region requirements. This is an availability note, not a maturity label.
Standalone web search for custom providers“Under development” and off by default.

I did not find a maturity label on ChatGPT Work, projects, image generation or plugins in the pages I read. For those, the docs say availability depends on your plan, platform, region, rollout and workspace settings, and that administrators can control access. In the CLI, codex features list shows known feature flags, their maturity stage and their effective state, and /experimental toggles experimental features.

3. Codex and ChatGPT Work for people who do not code

This is the part most developers miss when they recommend Codex to a friend. The docs describe Work as a way to get documents, analysis and research done, and say you can keep using Codex for research, documents and presentations if you prefer it. When you use ChatGPT Work in the desktop app, technical details such as Git or shell commands are hidden and the agent prefers nontechnical language and finished outputs. In the Codex view you see diffs and review views instead.

The docs give three starter prompts. Fill in the brackets with your own details:

IdeaExample prompt from the docs
Create a presentationReview the attached source materials and create an eight-slide presentation for [audience]. Focus on the main themes, include supporting evidence, and flag anything that needs human review. Return a draft for my review.
Compare options in a spreadsheetCreate a spreadsheet comparing the options for [decision]. Use the attached notes and source materials. Include the most important criteria, score each option, flag risks or missing information, and add a summary tab with a recommendation and next steps.
Set up a recurring updateEvery Monday morning, review new updates from @Slack and @Google Drive for [project]. Refresh the meeting agenda with decisions, blockers, owners, and open questions. Send me a draft before sharing it.

Notice the habits built into these prompts: they name the audience and the format, they say what good looks like, and they ask for a draft for review. That is the same discipline as Part 5. Other documented non-coding examples:

  • Research. The web search page suggests Research three approaches to reducing food waste in office cafeterias. Compare the evidence, costs, and implementation requirements. using deep research in Work, and says to review the report and its sources.
  • Images. Ask for a banner or illustration. The docs suggest a prompt of one to three clear sentences that names the purpose, the subject, the setting and style, and anything the image must not contain.
  • Ongoing responsibilities (a dot). The docs give examples such as keeping a sales proposal current as terms change, or updating a study as new measurements arrive and drafting a findings summary for review.
  • Websites. Sites says you can get started without writing any code, using documents and data you already have, and ask for changes as you go.
A gentle way to start without a terminal
  1. Install the ChatGPT desktop app (the quickstart lists macOS, Windows and Linux) and sign in with your ChatGPT account.
  2. Start with Chat to clarify your task. When you want a finished file, switch to Work.
  3. Give it a clear outcome, the sources to use, constraints, what good looks like, and when to stop for review (this list is the docs' own advice for Work).
  4. Open the result and check every section, slide or tab. The docs say to verify important numbers, names, dates and quotes.
  5. Ask for focused changes instead of starting over.

Everything in Parts 1 to 3 still applies in spirit: approvals before risky actions, a plan before big tasks, and written instructions so the agent does not start from zero. For a non-developer, those instructions might say who you are, what a project is for, and how you want results formatted. The docs describe project instructions for ChatGPT projects, and AGENTS.md for Codex folders.

For legal, financial, medical, security and other high-stakes decisions, the docs say to get expert review. Use the agent to support your judgement, not replace it.

The docs say longer or more complex Work tasks may use more credits, and recommend Chat for quick questions and short rewrites. They also recommend checking plan usage before starting a large task. For plans and limits, see Pricing, and remember that conversations with your dot do not count toward usage limits while tasks it starts in Work or Codex do.

5. Your first week: a day-by-day plan

This plan is my own suggestion, not an official curriculum. It uses short sessions that build on each other, and every day links to the part of the series that explains it. Aim for 20 to 40 minutes a day on a small project you know well. Keep the same project all week.

DayDoDone when…Read
1Install Codex (the desktop app or the CLI), sign in, and open a small project. Ask five questions: what it does, how to run it, where the main entry point is, what technologies it uses, how the folders are organised. Run /status to see the model and approval settings.You can explain the project to a friend using only Codex's answers, and you know how to quit.Part 1
2Type /plan and ask for a plan for a small change. Read the plan, approve it, then ask Codex to run the tests or a check.The change works and a test or check proved it.Part 5
3Run /init to generate an AGENTS.md scaffold, then trim it to what Codex would get wrong without it. Start a new chat with /new and check that it follows a rule you wrote.AGENTS.md is short and every line is specific, and a fresh chat obeys at least one rule.Part 2
4On a new Git branch, ask Codex to make a change. Read /diff, then run /review for a second opinion on your working tree.You reviewed the diff and the review comments before committing anything.Part 5
5After a long chat run /status and /usage, then /compact or /new, redo a small task and compare. Try the same task with another model via /model.You can say roughly what changed the token numbers and which model fit the task.Part 3 and Part 4
6Add one extension: a skill for something you repeat (/skills), a plugin you trust (/plugins), or one MCP server (/mcp to list tools).You used it once and can say what it saved.Part 6
7Review the week. Delete stale AGENTS.md lines. Run /recap, ask Codex to write a handoff note, then start a fresh chat from that note. Optionally try one non-code task in Work.The new chat picks up where you stopped without you retelling the story.Part 3 and Part 7

After week one: add automation only when you have a repeatable job (Part 7), and bring teammates in with shared, committed files rather than telling everyone to copy your setup.

6. Ten practice exercises

Learning sticks when you do things. These are my own exercises, built from the commands and prompts in the docs. Do them on a throwaway branch or a practice project. Each has a hint or a model answer.

#ExerciseHint or solution
1Ask for an overview, then trace how one feature works from the screen to storage.Ask for the entry point first, then name the feature. Ask for a list of files in the order the data flows.
2Introduce a small bug on purpose. Describe only the symptom and the likely location, and ask Codex to write a failing test first, then fix it.Ask it to show the failing test result before the fix and the passing result after.
3Pick a function and ask for a refactor that keeps behaviour the same, then have it run the tests.If tests do not exist, do exercise 4 first.
4Ask Codex to find untested functions, add tests, and run them.Limit it to one file at a time, so the diff stays reviewable.
5Turn a vague idea into a short SPEC.md by asking Codex to ask you questions first, then build it in a new chat.The docs suggest asking the agent to question you (“Ask me questions before you continue”). Use /new for the clean start.
6Give a vague prompt on purpose, correct it twice, then use /new and restate it carefully. Compare.Expect the second attempt to be faster and cleaner. The lesson is when to restart.
7Use /fork to try two approaches to one problem, then compare the results with /diff.A fork copies the chat into a new one, so your first transcript stays intact.
8Run one task on two models and compare quality, time and token use.Use /model between runs and /status after each. See Part 4 for the models.
9Write a three-line AGENTS.md rule for a mistake Codex keeps making, and see whether the mistake stops.Make it specific, for example the exact test command to run before finishing.
10Write a one-line script around codex exec that summarises git log, then ask for JSON events and read them with jq.Example: codex exec "Summarise the last 20 commits for a changelog: $(git log --oneline -20)". Add --json for newline-delimited events, or -o file.txt to save only the final message.

For a non-coding practice round, try one of the Work prompts from section 3 on your own notes, and ask the follow-up questions the docs recommend: What sources did you use? and What assumptions did you make?

8. Staying current

Codex, the models and the docs all change quickly. A few habits keep you from being surprised:

  • Update the CLI. codex update checks for and applies an update when your installed release supports self-update, and the docs show the installer commands for macOS, Linux and Windows. Part 1 has the details.
  • Read the weekly digest. The What's new page is a weekly digest of ChatGPT and Codex features. For example, it announced creating a dot in the mobile app on 9 October 2026.
  • Check model notices before you pin one. The scheduled tasks page, for instance, says GPT-5.5 retired from Codex with ChatGPT sign-in on 14 October 2026 and points to gpt-6.1-sol as the replacement where your plan allows it. Part 4 covers models.
  • Check feature flags. codex features list shows each flag's maturity and state.
  • Re-audit your setup now and then. Run codex doctor, prune AGENTS.md, and delete plugins and permissions you no longer use.
  • Remember this series is a dated snapshot. Everything here was checked against the official pages on 18 October 2026. When your version behaves differently, believe the docs.

Ten rules to remember

  1. The context window is the scarce resource. Keep it clean.
  2. The agent does not remember by itself. Your written instructions do.
  3. Plan before you implement, unless the change is one sentence.
  4. Give Codex a check it can run, and ask for evidence.
  5. Work on a branch and read the diff.
  6. Start with approvals on and a sandbox that fits the task. Treat --yolo as a last resort inside an isolated runner.
  7. Treat web results and untrusted content as untrusted.
  8. Correct early; after two failed corrections, start a new chat.
  9. Prune AGENTS.md, skills, plugins and permissions regularly.
  10. When in doubt, check the official docs.
